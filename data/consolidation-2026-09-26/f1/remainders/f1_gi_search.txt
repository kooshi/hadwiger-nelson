**Two independent ways a search here silently misses, and you have to be right about both: the regex ENGINE and the FILE SELECTION.** Both measured 2026-09-09, after one of them cost a wrong audit result.

**(1) The engine. `grep -E` on this machine is `ugrep`, not GNU grep, and it silently under-matches alternation inside a repeated group:**

``` ^\s*(private )*theorem              matches `private theorem foo` ^\s*(private |protected )*theorem   DOES NOT MATCH the same line

```

An inventory of this library's Lean declarations written with the second shape returned **5,093 names where the true count is 5,700** — a silent **10.6%** undercount, which reported two declarations as deleted that were sitting in the file and would have reported a clean bill on ones that really were gone. `rg` and `grep -P` both give 5,700 and both match the failing pattern.

**(2) The file selection. `rg` respects `.gitignore` by default**, and in this repository that hides `.lake/` (13 GB) and `build/` — which is where the measurement artifacts the ledger cites live. Measured on a whole-repo string search: **`rg` 108 files, `rg -uu` 408** — a 74% blind spot. (Naming a hidden directory explicitly works; it is recursive discovery from `.` that skips it.)

**So:** `rg` for searching SOURCE — correct engine, and the `.gitignore` skip is exactly what you want there. […] **Never a bare `grep -E` alternation-in-a-star for a count you intend to believe.** The gate scripts are unaffected — checked, not assumed — because their alternations (`^(VACUOUS|STALE) `) are not inside a repetition.

*This is `G21` wearing a tool's clothes, twice: the negative measured the instrument. And a 10%-blind extractor reporting "2 lost" reads exactly like a correct one, which is why the two names were chased into the source rather than believed.*

[…] Vary the statement — `= true` versus `decide (…)`, an `iff` versus an implication — before concluding Mathlib lacks something. `Nat.testBit_two_pow_sub_one` was reported missing here on exactly that error.

[…] Grep the toolchain source.** `grep -rn "<name-fragment>" $(lean --print-prefix)/src/lean/` searches *core*, which `exact?` will find but a search of `.lake/packages/mathlib` will not, and which a memory of "Mathlib has/lacks X" cannot cover at all. Three claims of absence have been wrong here — `Nat.ldiff`, `Nat.testBit_two_pow_sub_one`, and `Nat.ne_zero_and_sub_one_eq_zero_iff_isPowerOfTwo`, the last budgeted at 30–40 lines plus a Mathlib contribution before a grep found it complete in `Init.Data.Nat.Power2.Lemmas`. **Grep the source before writing the proof, and before writing that it is missing.**
