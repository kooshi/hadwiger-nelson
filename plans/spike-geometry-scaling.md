# Spike — the geometry check does not have to scale with the edge count

*Measured 2026-07-29 on de Grey's certified graph.*

**Finding: 7,877 edges have only 67 distinct difference vectors, up to sign.** A ratio of 118:1.

```
edges                       7877
distinct differences         133
distinct up to sign           67
most common difference       used 154 times
```

That is not luck. These graphs are built by *rotating and translating copies of a small base set*
(`tools/degrey.py` composes rotations about several centres), so the set of edge difference vectors is
generated by a handful of primitives no matter how many vertices the construction ends up with.

## Why it matters

Distance depends only on the difference. `Pt.distSq p q` is a sum of squares of `p - q`, so if

* `normSq v = denom²` is verified **once per distinct difference** (the expensive part: two
  squarings in `ℚ(√3,√5,√7,√11)`, ~272 leaf multiplications), and
* `verts j - verts i = v` is verified **per edge** (a subtraction and a comparison: ~32 leaf
  operations, no multiplication at all),

then every listed edge is certified. The expensive work becomes **O(distinct differences)** instead
of **O(edges)**.

Projected for de Grey: 67 norm identities plus 7,877 cheap equalities, against 7,877 norm identities
today. The per-edge cost should fall from the measured 0.045 s to roughly 0.005–0.01 s, and the term
that grows with graph size is now the cheap one.

## Why it matters much more for the hunt

M04's geometry cost 357 s of processor time at 7,877 edges. A 6-chromatic candidate could plausibly
carry 10⁵–10⁷ edges, which at today's rate is **1.25 hours to 5 days per candidate** — fatal for a
search that must test many. Under this scheme the expensive part stays near-constant, because a
rotation-generated graph with a million edges still has a small difference set. **This is the
difference between a search instrument that can certify what it finds and one that cannot.**

## The shape it implies

`UDCert` gains a difference table, and `ValidOn` changes from "recompute the squared distance" to
"look up the claimed difference and confirm the subtraction". Sketch:

```lean
structure UDCert (n : ℕ) where
  verts  : Fin n → Pt
  diffs  : PtTable            -- the distinct difference vectors, as points
  edges  : List (Fin n × Fin n × ℕ)   -- endpoints plus an index into `diffs`
  denom  : ℤ
```

with two checks — `diffs.all fun v => v.normSq = denomSq` (67 of them) and
`edges.all fun (i, j, k) => verts j - verts i = diffs.get k` — and the soundness theorem composing
them. The untrusted generator supplies the index; a wrong index makes the check fail, never a
theorem false, which is this project's standing arrangement.

**Not yet measured:** the actual per-edge cost of the subtraction-and-compare form, and whether
`PtTable`'s pivot lookup at 67 entries is free (it should be — six levels).

**Note the ordering risk:** the edge list would change shape, and M05's certificates index edges by
position. Do this either *before* M05's certificates are generated or *after* they are retired.
